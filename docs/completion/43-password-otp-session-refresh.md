# Password/TOTP session and refresh acceptance

Five shared lifecycle cases now run through Playwright and randomized Cucumber in Chrome/Edge, separately from the seven baseline cases. Each invocation owns its account, enrollment, browser context, and captured token material.

The browser lesson retains its existing policy: it clears local sign-in at access-token expiry and performs no silent refresh. The expiry case checks identity before expiry, observes clearing afterward, then completes password and TOTP again despite the existing provider cookies. Protocol refresh is exercised by the runner's private request context, not by a new UI refresh feature. A valid refresh must preserve subject, username, client, issuer, and lesson audience, and its token must still fail at all three business APIs with a valid customer certificate. Logout must invalidate refresh. A different public client must reject the OTP refresh token, followed by a successful same-token correct-client control. Actual client-session expiry must also reject refresh and leave the lesson signed out.

Only lifecycle fixtures in a fresh disposable `magic-shop-otp-*` project override the OTP client's access-token lifetime to 20 seconds and client-session maximum to 45 seconds. Realm lifetimes and other clients are unchanged. Server-returned lifetime bounds are checked before waiting. No clocks or token claims are altered. Policy ownership is recorded privately before mutation; cleanup restores the original absent overrides and verifies restoration after each selection, including partial setup. Unexpected pre-existing lifetime settings or policy drift fail closed. Baseline selections run with the normal policy.

Reports retain only allowlisted names and normalized statuses. The explicit `baseline`/`lifecycle` provenance and runner/browser must match the inventory. Lifecycle reports use separate `chrome-playwright-lifecycle`, `chrome-cucumber-lifecycle`, `msedge-playwright-lifecycle`, and `msedge-cucumber-lifecycle` directories. Access/refresh tokens, passwords, enrollment keys, raw failures, and attachments are discarded. The gate now requires 48 OTP executions (28 baseline + 20 lifecycle), plus 128 separate protocol executions, for 176 required executions. Counts describe browser/runner executions, not 176 distinct behaviors. Retained local reports are under `artifacts/password-otp/magic-shop-otp-session-fixed-20261017/`; independently downloaded native reports are under `/tmp/otp-session-native-evidence/otp-attempt1/`.

Ten focused tests passed for client-only lifetime policy, private ownership state, recovery after partial mutation, restoration/drift rejection, report filtering, phase/count provenance, and runner failure cleanup. Syntax and whitespace checks passed.
