# SAML Cucumber parity

The 11 existing SAML behaviors now use one `checkSaml` model in Playwright and Cucumber. Each invocation creates and closes its own browser context; assertion, replay, signing-key, and token state is local to that invocation. The checks cover provider login with lesson issuer/client/audience and business-API denial plus logout, disabled provider users, application callback-state rejection, cross-protocol provider rejection, broker-state rejection, modified signed response rejection, replay rejection, an unchanged re-signed control, and correctly signed wrong-audience/wrong-recipient/expired assertions.

Cucumber runs these scenarios in random order. The ordinary runner resets fixture users and browser home/tmp volumes between passkey, OIDC, and SAML selections. Signed fixtures use the existing disposable IdP signing material and lesson recipient mapper; this increment changes neither the signing policy nor the authentication flow. These are controlled provider → Keycloak → app checks, not organizational-provider compatibility evidence. SAML role-mapping assertions remain open.

The Cucumber formatter uses the established allowlisted names, normalized pass/fail statuses, and shared report writer. Raw exceptions, attachments, SAML responses, keys, passwords, and tokens are discarded. Separate `chrome-saml-cucumber` and `msedge-saml-cucumber` phase directories are required by the exact-count gate. The inventory requires 102 protocol executions plus 28 separate Password/TOTP executions, or 130 executions. The additional 22 Cucumber executions repeat existing behavior through another runner; they are not 22 new authentication behaviors.

Eight focused source checks passed, covering report filtering, exact-count/provenance gates, existing-resource refusal, and failure cleanup/status preservation, including a new SAML-specific failure probe. Two signed-fixture tests passed in the pinned browser runner: valid signatures/correlation for each semantic variant and rejection of unsupported/ambiguous/unsafe fixture inputs. The host attempt could not load its incomplete XML dependency tree; it is not counted as a test pass. Syntax and whitespace checks passed.
