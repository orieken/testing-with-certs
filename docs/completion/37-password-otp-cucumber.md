# Password + TOTP Cucumber parity — implementation and acceptance

This increment adds the same seven Password/TOTP behavior checks to Cucumber in real Chrome and Edge. The required TOTP inventory grows from 14 Playwright executions to 28 executions across both runners; the complete protocol inventory becomes 84 executions. These include 14 additional runner-parity executions, not 14 new authentication behaviors. All 28 TOTP executions passed locally and natively. The latest native run independently passed the full 84-execution authentication inventory. These counts describe browser/runner executions, not 84 distinct authentication behaviors.

## Shared model and isolation

Playwright and Cucumber call `checkPasswordOtp` in `testing/teaching/password-otp.mjs`. Each invocation owns its browser context, enrollment secret, and OTP replay-window tracking. Separate fixture accounts serve audience/API denial, wrong-password, invalid/expired-code, disabled-user, cookie/logout, and account-isolation checks. Scenarios requiring an enrolled authenticator enroll their own account; none depends on another scenario having run first. The isolation case authenticates one account, destroys that context, then proves a fresh context has no inherited identity before enrolling the second account.

Cucumber executes the scenario outline with randomized order. The seven checks cover certificate-free route boundaries, enrollment and lesson-token/API boundaries, incorrect password, incorrect/expired OTP, disabled users, password/OTP enforcement despite SSO cookies, logout, and fresh-context account isolation. Both runners use the same model and fixture policy. The production lesson and Keycloak password/OTP flow remain unchanged.

The disposable runner resets users and removes browser home/tmp volumes between each Chrome/Edge × Playwright/Cucumber selection. Existing-resource refusal and Cucumber-failure cleanup/status preservation have dedicated passing source tests. The standard CI job runs all four selections and requires all 28 results.

## Credential-safe evidence and matrix

Both reporters use `otp-results.mjs`. It exports only allowlisted case names and normalized pass/fail outcomes; raw exceptions, attachments, tokens, passwords, and enrollment material are discarded. The report includes explicit `runner` metadata, and directories are now `chrome-playwright`, `chrome-cucumber`, `msedge-playwright`, and `msedge-cucumber`. HTML/JSON/JUnit results are safe summaries; no traces, screenshots, or videos are recorded.

The matrix gate requires all seven unique successful cases in all four selections, with correct browser, runner, and live-evidence provenance. Missing or mislabelled Cucumber reports cannot be replaced by Playwright results. Historical two-directory/14-case reports retain their original scope and do not satisfy this expanded gate. Reporter redaction, non-pass normalization, runner identity, exact counts, and failure cleanup tests passed before live validation.

A cached-container Cucumber dry run found all seven scenarios and steps with no undefined bindings. Its seven skipped scenarios were parser/binding checks only and are not counted as live passes. The first host dry-run attempt could not resolve the incomplete host dependency tree; container-based validation uses the pinned installed Cucumber dependency instead.
