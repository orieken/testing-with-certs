# Controlled external OIDC session and refresh acceptance

Five shared lifecycle checks run through Playwright and randomized Cucumber in real Chrome/Edge, separately from the five baseline OIDC checks. Each scenario owns its provider/broker account, private browser context, and captured token material.

The browser lesson retains its policy of clearing local identity at access-token expiry without silent refresh. The expiry case observes identity before expiry and its removal afterward, then requires a new real provider authorization request and a verified broker token for the same subject/username. Existing provider SSO cookies remain intact. The test permits provider SSO reuse or another credential prompt; it does not claim that expiry forces a provider password prompt. Refresh is exercised by the runner’s private request context. A successful broker refresh preserves subject/username, issuer, client, and lesson audience, and its token is rejected at all three business APIs with a valid customer certificate. Browser logout must invalidate the broker refresh token. A different valid public client in the same broker realm must reject the captured refresh token, followed by a successful same-token correct-client control. Actual broker-client session expiry must reject refresh and leave the lesson signed out.

Only lifecycle fixtures in a fresh disposable `magic-shop-auth-*` project override the `lesson-oidc` realm’s `oidc-spa` client access-token lifetime to 20 seconds and client-session maximum to 45 seconds. Provider policy, broker realm policy, and other clients are unchanged. Server-reported lifetimes are checked; no clocks or token claims are altered. The existing policy helper now allowlists three lesson clients. Private ownership state precedes mutation, null attributes explicitly restore absence, readback verifies restoration, and pre-existing overrides/drift fail closed. Fixture cleanup removes owned users from both provider and broker realms and restores client policy after each group and on exit. The pre-existing `account-console` public client is read back and validated before being used as the client-binding negative; it is not modified.

Separate `oidc-lifecycle` and `oidc-lifecycle-cucumber` report phases prevent baseline reports from satisfying lifecycle requirements. Reports retain only allowlisted names and normalized status; passwords, access/refresh tokens, raw failures, and attachments are excluded. The inventory requires 168 protocol executions (148 previous + 20 OIDC lifecycle) plus 48 separate Password/TOTP executions, for 216 total. OIDC itself now requires 40 executions. Counts describe browser/runner executions, not distinct behaviors.

The runner used Chrome 155.0.8059.84, Edge 154.0.4258.62, and Playwright 1.61.0. Twenty-three focused tests passed for client-policy scope, private ownership, partial mutation recovery, restoration/drift refusal, report filtering, phase/count completeness, full runner coverage, and lifecycle failure cleanup. Syntax and whitespace checks passed.
