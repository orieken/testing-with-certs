# Controlled external OIDC Cucumber parity

The five existing OIDC federation behaviors now use `checkOidc` in both Playwright and Cucumber: successful provider login with lesson issuer/client/audience and business-API denial, logout, disabled provider users, application callback-state rejection, cross-protocol provider rejection, and broker-state rejection. Login/audience/logout remain one inventory case. These are controlled `provider → Keycloak → app` broker checks, not direct cloud-provider compatibility evidence.

Each scenario owns and closes a fresh browser context. The success case establishes its own provider session; negative cases do not depend on earlier login. The ordinary protocol runner creates fresh fixture users and removes browser home/tmp volumes between each passkey and OIDC Cucumber selection. Both Cucumber features run with randomized order. Fixtures remain scoped to the disposable project.

The OIDC formatter shares the established allowlisted case names, normalized pass/fail outcomes, and HTML/JSON/JUnit writer. It discards raw exceptions and attachments and records only safe failure locations. Reports use separate `chrome-oidc-cucumber` and `msedge-oidc-cucumber` directories with explicit phase provenance. The executable matrix now requires 80 protocol executions plus the separate 28 Password/TOTP executions, for 108 required executions; the additional ten executions are runner parity, not ten new authentication behaviors.

Seven focused source tests passed across reporting, exact-count/provenance gates, and runner cleanup. The added OIDC-specific failure probe verifies status preservation, fixture cleanup, and skipping the next browser when OIDC Cucumber fails. Syntax and whitespace checks passed.
