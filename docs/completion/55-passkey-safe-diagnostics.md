# Safe passkey diagnostics and repeat acceptance

2026-10-18 (America/Chicago).

The diagnostic gap noted in completions 39 and 46 is closed: the custom Playwright reporter now forwards only strictly validated `PASSKEY_DIAGNOSTIC` lines, including lines split across stdout chunks. Records contain an allowlisted passkey case name, an enumerated stage, and Boolean state fields. Other stdout, unknown fields, non-Boolean state values, mismatched cases, malformed JSON, and oversized buffers are discarded. Both runners save validated events in `diagnostics.json`. Cucumber retains direct safe output and collects the same events for its report. Raw errors, page text, URLs, request bodies, usernames, credential IDs, signatures, and token values are not forwarded.

The shared model emits readiness observations before WebAuthn clicks, enrollment success/failure state, and altered-signature rejection success/failure state. `observationFailed` identifies an incomplete diagnostic sample. Original failures are rethrown; diagnostics do not replace the mandatory registration, token/audience/API, changed-signature submission, rejection, identity, or privacy assertions. Existing real-public-script delay fixtures and document-load waits remain intact.

A reusable disposable harness, `testing/run-passkey-reliability.sh`, ran the seven baseline scenarios twice across real Chrome/Edge and Playwright/Cucumber, resetting accounts and browser profiles between selections. Accepted project: `magic-shop-auth-passkey-reliability-fixed-20261018`. All **56/56 executions** passed without test retries. Both rounds retained delayed registration and authentication module controls, actual changed-signature submission, and rejection without identity. The independent repeat gate verified every expected case, browser, runner, round, diagnostic allowlist/readiness/rejection event, and nonempty confined recording. There are **96 videos**. Reports are in `artifacts/auth-lessons/magic-shop-auth-passkey-reliability-fixed-20261018/round-{1,2}`; `verification.txt` records the gate result.

This is local Linux amd64 browser execution under Apple Silicon emulation, not new native CI evidence and not the full protocol/lifecycle matrix. The seven Playwright cases intentionally select only the passkey subset of the broader `passkeys-federation` phase. Repetition does not increase the unique authentication inventory. Finite passes do not prove all earlier historical failures share a cause or cannot recur. Native verification of these new diagnostics remains the next TODO.
