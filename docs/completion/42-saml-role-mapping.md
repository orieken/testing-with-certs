# SAML role-mapping acceptance

The controlled provider exports the administrator-managed `lesson_role` user attribute as the signed SAML attribute `lesson-role`. Keycloak's built-in `saml-role-idp-mapper` maps the exact value `reviewer` to the non-composite client role `saml-spa.lesson-reviewer`. The mapper uses `FORCE` synchronization so later assertions can remove a previously imported mapping. Its existing exact-recipient guard remains a separate required mapper.

The SAML lesson client has full role scope disabled, an explicit scope mapping to its one lesson reviewer role, and a client-role token mapper that exports only this client's roles as `lesson_roles` in access tokens. No business-API role or audience is granted. All existing callback, PKCE, SAML signature/audience/recipient/expiry, and cross-protocol checks remain in the suite.

Four shared cases run through Playwright and randomized Cucumber in Chrome/Edge: exact-value mapping, absent attribute, unrecognized value (`administrator`), and role withdrawal on later login. The withdrawal case first logs in with a correctly mapped role, then opens a fresh context and re-signs a new correlated assertion after removing only `lesson-role`; the newly issued token must have no lesson role. This is controlled signed-assertion evidence, not an administrator changing the provider account mid-scenario. All four cases retain issuer/client/audience validation and rejection of their lesson token at all three business APIs, using a valid customer certificate. The acceptance covers newly issued tokens after login; existing-token expiry/revocation remains a shared follow-up.

Fixture users are separate per case and removed from both provider and broker realms. Provisioning verifies administrator-only source editing, exact mapper configuration, explicit role scope, non-composite client role, and expected mapper inventory. A bounded migration tightens an existing SAML client's full scope and adds its lesson-only claim mapper. Seven focused bootstrap/migration/drift/matrix tests passed. Three pinned-container signed-fixture tests passed, including valid signatures/correlation after removing the role attribute. Live bootstrap repetition succeeded against actual Keycloak readback without changing accounts.

The executable inventory adds four SAML cases per runner/browser: 128 protocol executions plus the separate 28 Password/TOTP executions, or 156 required executions. SAML itself requires 60 executions across both runners and browsers. Reports retain the fixed-name/status allowlist and exclude assertions, passwords, signing keys, and tokens.
